PROBLEMA CORREGIDO:
Las facturas/proformas antiguas ya no deben cambiar cuando se edita la ficha actual del cliente.

1. Supabase > SQL Editor.
   IMPORTANTE: usa el SQL de ESTA carpeta corregida. El anterior dio error por el bloqueo de proformas facturadas.

FUNCIONAMIENTO DESDE V65:
- Cada proforma guarda una foto de los datos del cliente al crearla.
- Una factura creada desde una proforma hereda la foto de esa proforma.
- Una factura sin proforma guarda la ficha existente en el momento de crearla.
- Cambiar posteriormente nombre, titular, DNI/CIF, teléfono o direcciones del cliente NO modifica los documentos anteriores.
- Se conservan los cambios de V64 (Modelo 347).

IMPORTANTE SOBRE EL HISTÓRICO:
El SQL congela los documentos existentes con los datos que constan AHORA en la ficha del cliente. No intenta inventar datos antiguos que la base de datos nunca guardó.

CORRECCIÓN DEL SQL:
- Durante el backfill histórico se desactivan temporalmente los triggers USER de proformas.
- Inmediatamente después del UPDATE se vuelven a activar.
- El trigger de protección de proformas facturadas NO se elimina.
- Si cualquier instrucción falla dentro de la transacción, PostgreSQL revierte también el cambio temporal de triggers.
